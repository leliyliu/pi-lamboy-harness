## 3. 问题 1：运行中的会话仍在跑旧版代码

```
pi 进程 91811 启动:  14:00:42
notify.ts mtime:    19:36:59   ← 晚于启动 5.5 小时
```

日志 `/tmp/pi-notify.log` 在 `12:57:41Z`（20:57 本地）记录：

```
[2026-10-22T12:57:41.958Z] settled mode=tui aborted=false err=false
[2026-10-22T12:57:42.080Z] osascript exit=0          ← 122ms 返回
[2026-10-22T12:57:44.970Z] afplay Glass exit=0
```

- `osascript exit=0` 是旧版日志格式，v5 会写 `dialog fallback exit=` 或 `pinotify spawned`；
- 122ms 返回证明走的是 `display notification`——即诊断报告里标注的**假成功通道**（投递被授权闸门拦下但仍 exit 0）。

⇒ 该会话实际收到的提醒只有声音，没有可见弹窗。**扩展代码在 pi 启动时载入内存，改文件不热更，必须重启。**

## 4. 问题 2：多屏下浮窗位置漂移（已修）

### 现象

连弹 3 次，抓窗口坐标：

```
第 1 次 → X = -362   ← 左侧副屏边缘附近（等于看不见）
第 2 次 → X = 1558   ← 主屏右上角（正确）
第 3 次 → X = 1558
```

### 根因

`pinotify.swift:91` 原代码：

```swift
guard let screen = NSScreen.main ?? NSScreen.screens.first else { exit(0) }
```

`NSScreen.main` 的 AppKit 语义是「**key window 所在屏**」，不是主屏。本机三屏布局：

```
screen[0] (0,0,1920,1080)        主屏，含菜单栏
screen[1] (-999,-982,1512,982)   左下外接
screen[2] (-1920,0,1920,1080)    左侧外接
```

焦点窗口落在副屏时，`NSScreen.main` 解析为 `screen[2]`，算出 `maxX - W - margin = 0 - 348 - 14 = -362`，浮窗弹到另一块屏，用户看不到。

### 修复

改为「鼠标所在屏 → 含菜单栏主屏 `screens[0]` → `NSScreen.main`」：

```swift
func targetScreen() -> NSScreen? {
    let mouse = NSEvent.mouseLocation
    if let s = NSScreen.screens.first(where: { NSMouseInRect(mouse, $0.frame, false) }) {
        return s
    }
    return NSScreen.screens.first ?? NSScreen.main
}
```

理由：鼠标位置是「用户此刻视线」的稳定代理，且与系统通知跟随活动屏的行为一致。

### 验证

| 场景 | 结果 |
|---|---|
| 鼠标在主屏，连弹 10 次 | 10/10 均为 `X=1558 Y=39 W=348 H=88`（主屏右上角） |
| 鼠标移到副屏 `(-1000, 500)` 后弹窗 | `X=-362`，落在 `screen[2]` 右上角——正确跟随 |
| 部署到正式路径 `~/.pi/agent/bin/pinotify` 后自测 | `X=1558 Y=39`，正确 |

备份：`~/.pi/agent/bin/pinotify.bak-20261022-213139`。

## 5. 附修：日志加 pid

`/tmp/pi-notify.log` 被多个 pi 进程共享 append，行首无 pid 时旧版新版记录混杂，本次诊断一度因此判错版本归属。`debug()` 已改为：

```
[ts] [pid] msg
```

## 6. 生效条件

- pinotify 新 bin 无条件立即生效（每次调用新进程）；
- notify.ts 的改动（v5 + pid 日志）**需重启 pi 会话**后才载入。
